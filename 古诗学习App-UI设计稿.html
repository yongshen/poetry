设计说明

产品定位、接口能力边界与本次设计的取舍。开工前请先确认这一节，它决定了后面所有页面为什么长这样。

产品定位

产品名诗泉·背诗（暂定，可改）
目标用户中小学生、备考人群、古典诗词自学者
核心场景每日打卡背诵 → 多模式默写检验 → 错句强化复习
差异点不是"读诗 App"，而是"背诗训练器"：把 37 万首语料转成可练的题
设备手机竖屏优先，单手可操作

接口能提供的

  • 随机抽诗，可按作者 / 朝代 / 体裁 / 单字筛选
  • 全文检索，带分页，可无限加载
  • 作者名录（13577 位，分页）
  • 朝代名录（11 个，含起止年份、英文名）
  • 体裁名录（17 种，含句数与每句字数）
  • 全库统计（371313 首）
  • 服务健康检查
  • 简繁双语全局切换

content 字段是逐句数组，这是默写类玩法（挖空、接龙、排序）能纯前端出题的关键。

接口没有的

  • 译文 / 注释 / 赏析 —— 无字段
  • 拼音 / 朗读音频 —— 无字段
  • 诗词详情接口 —— 不能按 id 单取一首
  • 作者作品集 —— 不能列出某人全部诗
  • 用户体系 —— 无注册登录，收藏与打卡只能存本地
  • 难度 / 教材分级 —— 无课标年级标签

设计上已规避：详情页数据由列表页透传；作者页改为"随机代表作"；练习数据全部本地存储。

⚠ 数据风险：诗词的朝代字段疑似有误。
抽样验证时，朱熹、文天祥、梅尧臣、方岳、曾几等宋代诗人，其诗词返回的 dynasty 全部标为"唐"，一次搜索返回的 20 条结果也清一色是"唐"；但作者列表接口里的朝代标注正常（有"宋"有"元"）。
影响："按朝代筛选诗词"可能返回错误结果。设计处理：朝代入口保留，但仅作浏览维度；开发阶段需先验证该字段，必要时改用作者的朝代间接推导。
关于"学习"的能力边界。
如果你想让用户理解诗意（译文、赏析、背景），现有接口无法支撑，需要自建内容库或接入第三方，这是独立的工作量。
如果你想让用户背熟默写，现有接口完全够用，本设计稿即按此定位展开。若要两者兼有，建议在开发前追加一轮内容源方案。

五个标签的职责划分

首页每天打开的第一屏。一首诗 + 一个任务进度 + 四个练习入口，不做信息堆砌
发现探索与检索。承载搜索、诗人、朝代、体裁四个浏览维度
练习核心。四种模式的选择与难度设定，进入后是全屏沉浸答题
收藏记忆管理。按复习紧急度排序，而非按收藏时间
我的数据与设置。打卡日历、简繁开关、服务状态

待你确认的点

  • App 名称：暂定「诗泉·背诗」，取自 API 品牌名，可换成你自己的名字
  • 每日任务量：默认 10 首，是否偏多？学生党可能只需 3–5 首
  • 复习间隔：1/3/7/15/30 天，是否符合你的教学节奏
  • 飞花令字库：暂定 8 个常用字（春月花风雪山水云），可扩展
  • 是否需要朗读：接口无音频，若需要得接第三方 TTS，是额外工作量
  • 是否需要译文：接口无译文，若需要得自建内容库
关于本地存储。诗泉 API 无用户体系，收藏、打卡、错句本、复习进度全部存在设备本地（App 端为本地数据库，Web 端为 localStorage）。这意味着换设备不会同步——如果需要同步能力，得自建后端，请提前告知。

状态与细节设计

加载、空、错误、离线四种状态，以及几个容易在开发时被漏掉的交互细节。

加载中

抽诗与搜索用旋转印章式 loading；列表页改用骨架屏，避免整屏闪白。

骨架屏

搜索结果与诗人列表用三行骨架，高度与真实卡片一致，防止布局跳动。

空结果
無

搜索无结果时给出建议：换更短的词、去掉筛选、或直接摇一首随机诗。

请求失败
!

显示"诗泉暂不可达"，提供重试与"改用本地收藏"两个出口，不弹阻断式对话框。

离线模式
離線

顶部一条克制的提示条。已收藏内容可正常读写，练习降级为错句本模式。

长标题截断

数年前有小词微雨后落花天娇态病恹恹怕人猜著是相思…›

实测存在 60 字以上的超长诗题，必须两行截断 + 省略号，详情页才展示全文。

答题手感

  • 选字后不立即判定，等用户点提交，允许改选
  • 判定后错字抖动一次再变红，正字用绿色渐显
  • 连对 3 题给一次轻反馈（印章浮现），不打断节奏
  • 整组完成后才展示统计，中途只显示进度条
  • 触控目标 ≥44×44px，候选字格不小于 52px

记忆曲线

  • 间隔 1 / 3 / 7 / 15 / 30 天递进
  • 答对升一级，答错回退一级并当天再现一次
  • 连续三次满级判定为"已背熟"，移出待复习
  • 收藏列表默认按复习紧急度排序，而非收藏时间
  • 全部本地计算，不依赖服务端

视觉细节

  • 诗文用楷体 + 大字距（letter-spacing 3px），营造竖排碑帖感
  • 朱砂印章只出现在：品牌、已背熟标记、判定错误
  • 卡片左侧一道朱砂细线代替重阴影，保持纸感
  • 繁体模式下整页联动，包括界面文案，不只诗文
  • 深色模式可作二期，色板已预留黛青作底色

开发前建议先定的四件事

① 朝代字段是否可信。建议开发第一步就抽样验证 random?dynasty=宋 的返回，若确认有误，朝代筛选功能需要改设计或下线。
② 是否需要译文赏析。若需要，得先解决内容源（自建 / 第三方），这会显著影响工期与产品形态，建议尽早定。
③ 名家资料预置范围。诗人详情页需要生卒年、称号、简介，接口不提供。建议先定预置多少位（50 / 100 / 300），这是一次性人工整理工作。
④ 技术形态。本设计稿为 Web/H5 视觉呈现。若要原生 App，界面可直接沿用，但需明确用 Flutter / React Native / 原生双端，以及本地存储方案。
